## Finding by finding

Columns:

- **Correct?** Whether the audit's claim holds against the code.
- **Audit's fix:** what the audit proposed.
- **Alternatives:** other options we considered.
- **Chosen:** what we are doing.
- **Phase:** when.

### Delivery, storage, pairing

#### 1. Receiver memory unbounded (P1) — Correct

**Evidence:**

- Every frame chains onto `controlQueue` (`receiver.ts` `enqueueData`).
- The sender's only brake is the per-lane `bufferedAmount` (4 MiB), which
  measures the *network* queue, not the receiver's disk queue.
- With a fast link and a slow phone disk, the queue grows with file size.

**Audit's fix:** receiver-driven credits or a window.

**Alternatives:**

| Option | Verdict |
|---|---|
| (a) Pause the DataChannels | Not possible. WebRTC has no receive-side pause. |
| (b) Ack every chunk | Simple, but chatty: about 16 messages per MiB. |
| (c) Stop-and-wait per file | Kills throughput. |
| (d) **Sliding window of byte credits** | Receiver reports cumulative consumed bytes every ~1 MiB. Sender keeps `sent − credited ≤ window` (16 MiB). This is TCP-style flow control: well understood, and memory ≤ window. |

**Chosen:** (d). See [ADR-001](../adr/ADR-001-receiver-flow-control.md).
Includes a stall watchdog and a version handshake. **Phase A**.

#### 2. Empty files "succeed" without being saved (P1) — Correct

**Evidence:** `done: offset >= f.size` marks a 0-byte file done at manifest
time, so its `file-end` is ignored and the sink never finishes.

**Audit's fix:** split "all bytes present" from "finalized and verified".

**Alternatives:**

- Skip empty files. Wrong: users expect the file to exist.
- Special-case size 0 in the sink. Leaves the root cause.

**Chosen:** the audit's fix. Every file goes through the same
finish → verify → `file-done` path, including the empty one (SHA-256 of
nothing). **Phase A**.

#### 3. Temporary filenames collide (P1) — Correct (see nuance)

**Evidence:** `partialName(leaf, size)` is the only identity.

**Alternatives:**

| Option | Verdict |
|---|---|
| (a) Random partial names | No collisions, but breaks resume. |
| (b) Name by content hash | The sender doesn't know the hash until it has read the whole file, so that would mean reading it twice. |
| (c) **Fingerprint of (path, size, lastModified)**, plus in-transfer de-duplication, plus a Web Lock per partial | Resume keeps working for "the same file sent again". Distinct files never share a partial, and two tabs can't write the same partial. |

**Chosen:** (c). See [ADR-002](../adr/ADR-002-partial-file-identity.md).
Final-name reservation also runs under a Web Lock. **Phase A**.

#### 4. Writes outside the declared file (P1) — Correct

**Evidence:** `JSON.parse(text) as ControlMsg`. The offset is computed from
an unchecked `chunkIndex`.

**Audit's fix:** strict validation of every message and frame.

**Alternatives:**

- A schema library (zod/valibot). It adds a runtime dependency for about 10
  message shapes.
- Hand-written validators with tests. Zero dependencies, and enough for a
  small protocol.

**Chosen:** hand-written validators in `packages/protocol`.

- **Manifest:** limits on file count and name length; finite, safe,
  non-negative sizes; unique ids; sizes must sum to the total; chunk size
  within bounds.
- **Frames:** must address a known file; chunk index within range; payload
  length exactly what that chunk must carry.
- **Duplicates:** tracked with a per-file bitset (1 bit per chunk, about
  100 KB for 50 GB).
- **State:** a second manifest is a protocol error.
- **Tests:** adversarial-peer tests. **Phase A**.

#### 5. QR generation broken (P1) — Correct

**Evidence:**

- `drawFormatBits` writes the first format copy at `m[8][i]`, the transpose
  of the standard position `m[i][8]`. Same for the second copy.
- Versions 7+ never draw the 18-bit version information and never reserve
  its area.
- The quiet zone is 2 modules; the standard is 4.

**Alternatives:**

| Option | Verdict |
|---|---|
| (a) Replace with an npm QR library | A runtime dependency for ~60 lines of fixes. |
| (b) Vendor Nayuki's reference file | Good, but it means fetching and maintaining a copy. |
| (c) **Fix the three defects and prove them with an independent decoder in CI** | Every version 1–10 and many payloads are decoded by `jsQR` (dev-only dependency). |

**Chosen:** (c). The test is what makes this trustworthy. A real-phone scan
is added to the release checklist. **Phase A**.

#### 6. `/about`, `/features`, `/privacy`, `/blog`, `/terms` crash on direct load (P1) — Correct

**Evidence:** `routeOnLoad()` runs at module line ~1745. It calls
`showBlog()`/`showLegal()`, which read `const`s declared ~250 lines later
(temporal dead zone).

**Alternatives:**

- Move the constants up. Brittle: the next edit re-breaks it.
- **Run the route handling from one explicit `bootstrap()` at the end of
  the module.**

**Chosen:** bootstrap at the end now. Routing and content move into their
own modules in Phase E. A smoke test loads every route. **Phase A**.

#### 7. Save fallback doubles I/O and space (P2) — Correct

**Chosen:** verify the **partial** before publishing the final name. Then a
failed check never creates a final file, and the copy fallback no longer
needs a second full read. Check free space before the copy fallback.
**Phase B**.

#### 8. Sessions can wait forever (P2) — Correct

**Evidence:**

- `awaitAck` has no timeout and no close handling.
- The sender's `onclose` is installed only after the ack.
- `hostSendChannel` doesn't catch `send()` exceptions.
- There are no worker `error`/`messageerror` handlers.

**Chosen:**

- **Phase A**, inside the sender rewrite for #1: one control dispatcher
  installed at start, close handling from the beginning, a manifest-ack
  timeout and a credit-stall watchdog.
- **Phase B:** worker error propagation and awaited cleanup.

### Signaling and security

#### 9. Malformed requests create immortal rooms (P1) — Correct

**Evidence:**

- `isClientMsg` only checks `type`.
- `ttlSeconds: "x"` gives `NaN` expiry, and `NaN < now` is false, so the
  room is never pruned.

**Chosen:** strict validators per message type, bounded device fields, TTL
clamped to [60 s, 4 h], and environment variables validated at startup.
**Phase A**.

#### 10. Membership leaks (P1) — Correct

**Evidence:** a second create/join overwrites `ws.data.room` without
leaving the first.

**Alternatives:**

- Auto-leave the old room.
- **Reject with `already-in-room`.**

**Chosen:** reject. A client must send `leave-room` first. It's explicit and
easy to test. **Phase A**.

#### 11. Spoofed X-Forwarded-For bypasses limits (P1) — Correct

**Alternatives:**

| Option | Verdict |
|---|---|
| (a) Take the right-most entry | Wrong if there are 0 or 2 proxies. |
| (b) **`TRUST_PROXY_HOPS=N`** | Default 0 uses the socket IP. With N > 0, take the Nth entry from the right, which is the address the trusted proxy saw. |
| (c) Allow-list of proxy CIDRs | Most precise, but platform IP ranges change. |

**Chosen:** (b), with `render.yaml` setting `1`. Plus a global connection
cap and a per-IP connection cap. **Phase A**.

#### 12. Eight-peer rooms (P2) — Correct

**Chosen:** default capacity **2**. A third joiner gets `room-full`, which
the UI already explains. Multi-receiver comes later with its own design.
**Phase A** (one-line change).

#### 13. Static TURN credentials in public JS (P2, conditional) — Correct

**Chosen:** a `/turn-credentials` endpoint on the signaling server that
mints short-lived Cloudflare TURN credentials. It is rate-limited and only
issued to a socket that is in a room. **Phase D**, before TURN is enabled.
Until then, ship **without** TURN rather than with static credentials.

#### 14. Signaling hardening (P2) — Correct

**Chosen (Phase B):**

- Drop slow sockets on backpressure.
- Optional `ALLOWED_ORIGINS`.
- Per-socket message limits, separate from the coarse per-IP limits.
- Join-guess limiter.
- Idle-socket timeout.
- Counters with no codes, SDP or file data.

#### 15. Passphrase threat model (P2) — Correct (see nuance)

**Chosen:**

- **Phase A:** AES-GCM additional authenticated data =
  `transferId|fileId|chunkIndex`, so a chunk can't be replayed or moved to
  another position.
- **Phase C:** a written threat model in `SECURITY.md`. No stronger claims
  until an external crypto review.

## Release gates (adopted from the audit, made concrete)

A public launch (Phase D) needs **all** of these:

1. Every P1 has a regression test, and the tests pass in CI.
2. Receiver memory stays under the declared window (16 MiB + one frame per
   lane) in the slow-disk test, whatever the file size.
3. Success is shown only after the file is verified and finalized. Empty
   files are included.
4. No console errors on `/`, `/about`, `/features`, `/blog`, `/privacy`,
   `/terms` and `/?c=CODE`.
5. Signaling churn test: 1,000 create/join/leave/disconnect cycles leave
   **0** rooms.
6. QR codes decode in CI (jsQR, versions 1–10) **and** on a real iPhone and
   Android camera.
7. The manual device matrix (`docs/ROADMAP.md` §2a) is filled in for the
   deployed staging site.
8. `bun audit` shows no high-severity advisories.
